Idea

Trust is a feature.

Because Ujimu answers legal and regulatory questions, the system must be conservative, traceable, privacy-aware, and operable before production use.

Scope boundary

Practical hardening, not an observability platform.

  • Use first-party app controls and local operational signals.
  • Do not add external APM, log aggregation, metrics, SIEM, or alerting vendors in this slice.
  • Keep readiness safe: booleans and counts, never secret values or paths.
  • Keep implementation small enough to verify with acceptance tests.
HTTP surfaces

Expose liveness and readiness without leaking internals.

Security headersBaseline headers apply to app and API responses through server middleware.
/healthzPublic liveness endpoint returns only a minimal OK payload.
/api/admin/ops/readyzAdmin-only readiness returns safe booleans and numeric migration count.
Operational logs

Use daily JSONL files as the MVP sink.

  • Write to `<UJIMU_DATA_DIR>/logs/operational/operational-YYYY-MM-DD.jsonl`.
  • Each line is one event with timestamp, category, event name, severity, optional specialist ID, and sanitized metadata.
  • Console output stays minimal and derives from the same sanitized event payload.
  • No SQLite operational-events table was added in this slice.
Privacy rule

Log decisions, not secrets or contents.

  • Never persist raw questions, answers, OTP codes, cookies, JWTs, webhook secrets, or document contents.
  • Do not store full email or phone contact values in operational logs.
  • Safe metadata includes outcomes, counts, provider names, booleans, and error codes.
  • Billing webhook rejection and processing outcomes are logged with sanitized fields only.
Hardening targets

Protect the boundaries users can cross.

  • Uploads must stay inside the selected specialist `raw/` directory.
  • Chat, history, ingestion, and admin operations stay scoped by validated specialist ID.
  • Permanent deletion removes user-visible dependent data.
  • Billing webhooks activate subscriptions only after verified secret-protected confirmation.
SQLite and delivery

Small operations still need discipline.

MigrationsSchema changes are tracked with `schema_migrations`; readiness reports migration count only.
BackupsThe runbook documents SQLite backup and restore commands plus integrity checks.
CIGitHub Actions runs install, tests, typecheck, build, and high-severity audit.
SecretsSession, OTP, admin, billing, provider, and passkey settings stay server-side.

Verification

Acceptance checks define the slice.

  • Security headers apply to app responses.
  • Operational events are daily JSONL and sanitized.
  • `/healthz` is minimal; readiness is admin-only and safe.
  • Uploads reject traversal and remain inside `raw/`.
  • CI and the operations runbook cover the deployment quality gate.
Future candidates

Known hardening gaps belong in later slices.

  • Log retention, archival, deletion, and explicit file-permission policy.
  • Stricter CSP policy and environment-specific security-header tuning.
  • Readiness degraded-state semantics and operational dashboards.
  • Backup restore drills, incident-response workflow, alerting, APM, metrics, and external log aggregation.
