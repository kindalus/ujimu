Slice 11

Security, operations & observability

Harden the product around uploads, auth, specialist isolation, quotas, billing callbacks, deletion, and operational visibility.

privacy uploads logs SQLite isolation
Idea

Trust is a feature.

Because Ujimu answers legal/regulatory questions, the system must be explicit, traceable, conservative, and observable.

Upload safety

Files are data, never executable instructions.

  • Prevent path traversal and unsafe filenames.
  • Store raw files inside the specialist raw/ directory only.
  • Validate file type and readability where possible.
  • Do not run OCR or executable document macros in the MVP.
Specialist isolation

A chat cannot leak across domains.

  • Chat context is limited to the selected specialist.
  • Admin actions must target a single specialist by validated ID.
  • Source metadata and histories are partitioned by specialist ID.
  • Deleting a specialist removes associated customer histories.
Secrets

Providers require secret hygiene.

  • Keep Appy Pay, Stripe, SendGrid, and session secrets in environment variables or a secret manager.
  • Never commit .env files.
  • Do not expose server-only config to Nuxt public runtime config.
  • Webhook signing secrets must be verified server-side.
SQLite operations

Small database does not mean casual database.

  • Use migrations and a schema_migrations table.
  • Apply safe transaction boundaries for destructive operations.
  • Plan backup and restore procedures before production use.
  • Avoid long-running write locks during ingestion or analytics jobs.
Observability

Log decisions, not secrets.

ChatSpecialist, outcome, timings, citation presence, insufficient-context results.
QuotaAllow/deny decisions and effective policy.
IngestionPending, processing, ingested, failed with safe errors.
BillingProvider events, confirmation, activation, expiry.
Deletion and privacy

Permanent deletion must be complete.

  • Conversation deletion removes messages and citations.
  • Specialist deletion removes associated customer histories.
  • Deleted content should not remain visible in history, admin lists, or chat context.
  • Operational logs should avoid retaining sensitive message content unnecessarily.

Success conditions

What must be true when the slice is done.

  • Uploads cannot escape the intended specialist raw/ directory.
  • Chat, history, ingestion, and admin operations are scoped by validated specialist ID.
  • Secrets are not exposed to client bundles or committed files.
  • Billing webhooks only activate subscriptions when verified.
  • Permanent deletion paths remove user-visible data and dependent records.
  • Operational logs provide enough context to diagnose failures without storing unnecessary sensitive content.
