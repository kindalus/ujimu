Slice 4

Specialist chat, streaming & citations

Let an anonymous first-time visitor choose a specialist, ask repeated questions, receive streamed grounded answers, and see citations or a safe fallback each time.

streaming citations AI notice specialist scope
Idea

The chat is scoped before the first token.

A user must choose a specialist before asking. Each submitted question then runs through the same scoped engine: selected wiki only, streamed answer, citations at the end, or a fail-closed insufficiency response.

Refined direction

Hybrid engine, public chat loop.

  • Build the anonymous first-time visitor path first.
  • Allow repeated questions in the same selected-specialist page.
  • Use a swappable chat engine: fake deterministic runner in tests, with real Pi chat deferred until citation hardening.
  • Fail closed when wiki evidence is missing instead of using general model knowledge.
Not doing

Keep the first chat slice sharp.

  • No authentication, subscriptions, quotas, or payments.
  • No durable conversation history or edit-and-rewind semantics.
  • No admin upload or ingestion controls.
  • No cross-specialist context switching inside a single response.
Assumptions to validate

The smallest useful answer still needs trust signals.

  • Users will understand that citations, not fluent prose, are the trust anchor.
  • Existing wiki/source metadata is enough to decide whether to answer or fail closed.
  • Streaming improves perceived usefulness enough to justify protocol complexity.
  • A fake runner can prove product behaviour while Pi integration remains explicitly gated.
Locked decisions

Contract and grounding.

  • The chat endpoint streams NDJSON over POST with delta, citation, done, and error events.
  • Missing evidence is a normal assistant response with grounded=false, not an HTTP error.
  • The fallback explains, without technical detail, what kind of official source or context would be needed.
  • The server performs a deterministic evidence pre-check, and the chat engine must still fail closed for question-specific gaps.
Locked decisions

Runtime and UI behaviour.

  • Conversation state is in-memory page state only for this slice.
  • Pi chat remains inactive in this slice, even though the future activation flag is reserved as UJIMU_PI_CHAT_ENABLED=true.
  • When no real chat runner is configured, the endpoint streams a service-unavailable assistant response with grounded=false.
  • The Pi chat runner uses cwd = specialist root with read/search tools only and is instructed not to read raw source files at answer time; this is a prompt-level restriction to revisit after testing.
  • For this slice, engine citations use the structured sourceTitle/sourceFile/articleRefs contract, but Pi citation-control hardening will be revisited with the raw-access restriction.
  • The Pi chat runner does not parse model citations in this slice; tests use an injected fake runner and production falls back safely until Pi chat hardening is implemented.
  • If a user asks while an answer is streaming, the UI shows a visible queue of up to three pending questions where pending questions can be cancelled or reordered.

Server contract

One chat endpoint, specialist required.

POST /api/chat
{
  "specialistId": "iva",
  "question": "...",
  "clientTimezone": "Africa/Luanda"
}

response content-type: application/x-ndjson
stream events: delta | citation | done | error
Response discipline

The assistant does not fill gaps with general knowledge.

  • Use only the selected specialist wiki and its traceable sources.
  • If the wiki cannot support the answer, stream a normal assistant response explaining that the current sources are insufficient.
  • The insufficiency response should also say, in non-technical terms, what kind of official source or context would be needed to answer safely.
  • Do not cite internal wiki page names to end users.
  • Keep citations until the end of the answer.
Citation format

Legislation answers cite instruments and articles.

{
  "type": "citation",
  "citation": {
    "sourceTitle": "Código do IVA",
    "sourceFile": "raw/codigo-iva.md",
    "articleRefs": ["Artigo 1.º", "Artigo 12.º"]
  }
}
The UI renders citations in a separate Fontes section below the streamed answer. The assistant text does not need to contain citation markup.
AI notice

Every specialist makes the limitation visible.

User-facing copy should clearly say that content is generated by AI, may contain errors, and should be confirmed against the cited sources.

Success conditions

What must be true when the slice is done.

  • An anonymous first-time visitor cannot ask a question until a specialist is selected.
  • Each submitted question streams progressively rather than appearing only at completion.
  • If the user submits while an answer is streaming, the question appears in a visible queue and can be cancelled or reordered before it runs.
  • The visible queue accepts up to three pending questions, with controls to cancel and reorder them.
  • The user can ask another question in the same selected-specialist page and get the same streamed citation/fallback behaviour.
  • The final response includes citations at the end when the answer is substantive.
  • Unsupported questions or missing wiki evidence result in an insufficiency response, not a hallucinated answer.
  • The AI-generated-content warning is visible in the specialist chat experience.
