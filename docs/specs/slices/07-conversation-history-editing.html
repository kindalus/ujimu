Slice 7

Conversation history & editing

Give registered users the latest 20 sessions per specialist, with resume, hard delete, destructive edit behaviour, and an AI-generated title after the first answer.

20 sessions resume hard delete truncate after edit AI title
Idea

History is useful, but bounded.

Registered users should return to prior specialist sessions without the product becoming a permanent archive.

Scope

Only registered users get history.

  • Anonymous users do not get cross-session history in the MVP.
  • Messages sent before login are not retroactively migrated into a registered history.
  • The first authenticated question for a selected specialist automatically creates a conversation.
  • History is grouped by specialist and shown as a compact panel on the main chat page.
  • The list shows the latest 20 conversations/sessions per specialist.
  • Conversation deletion is permanent.
  • History endpoints require authentication: anonymous users receive 401; missing or cross-user conversations return 404.
Data model

Keep conversations linear.

conversations
  id, user_id, specialist_id, title, created_at, updated_at
messages
  id, conversation_id, role, content, parent_order, created_at
message_citations
  message_id, source_file, source_title, article_refs_json, shown_order
conversation_title_jobs
  id, conversation_id, status, created_at, completed_at
Locked decision: assistant citations are stored as exact snapshots of what was shown to the user, and restored conversations render those snapshots instead of recalculating citations from the wiki.
Conversation title

Let AI name the session after it has context.

When the first assistant response completes, generate an indicative title from the first question, the first answer, and the selected specialist. The title is for navigation only and is not used as answer-grounding evidence.

Locked decision: use a hybrid path. Try to generate the AI title quickly after the first answer with a 5 second timeout; if generation fails, times out, or no title provider is configured, keep a temporary title with pending status. This slice stores pending state but does not implement a background regeneration worker.
Resume

Continuing a session appends to the current timeline.

A limited slice of prior messages may be sent as conversational context for disambiguation, but never as grounding evidence or a replacement for wiki citations. The initial window is the first 5 messages plus the last 10 messages, de-duplicated for short conversations.

Edit behaviour

Going back rewrites the future.

Only authenticated user-authored question messages can be edited. When an edit succeeds, the original question and every later message are permanently removed, then the edited question and new assistant response are appended after the remaining prefix with new message IDs. If replacement generation fails or the stream is incomplete, the old conversation remains intact.

Deletion

Delete means delete.

  • Deleting a conversation removes messages and citations from SQLite.
  • Deleted conversations do not appear in history or analytics views as user history.
  • Specialist deletion also deletes all related customer conversations.

Success conditions

What must be true when the slice is done.

  • A registered user sees at most 20 latest sessions for a selected specialist.
  • Opening a session restores its messages and allows continuation.
  • Deleting a conversation permanently removes it from the user history.
  • Editing an earlier question permanently removes all later messages before saving the replacement path.
  • After the first assistant response, an AI-generated title is stored using the question, answer, and selected specialist as input.
  • The chat stream emits a history event with persisted conversation/message IDs after authenticated history is saved and before the final done event.
  • Fallback answers shown to the user are saved after completion; technical failures, partial streams, and quota denials are not saved as conversation messages.
  • History for one specialist never appears under another specialist.
