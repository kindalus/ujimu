Slice 19

Página de subscrição

Mover plano, estado e checkout mock para /subscription, deixando o chat livre de blocos de facturação permanentes.

Referências

Origem e dependência

  • Depende dos slices 16 a 18.
  • Arquitectura aprovada: rota /subscription.
  • Live payments continuam fora do lançamento inicial.
  • O preço-alvo permanece 50.000,00 AOA por trimestre.
Escopo

Subscrição como tarefa própria

  • Criar pages/subscription.vue ou equivalente Nuxt.
  • Mostrar plano, estado actual, aviso de expiração e acções mock existentes.
  • Accionar login a pedido se o utilizador tentar subscrever sem sessão.
  • Remover a UI de subscrição permanente da página de chat.
  • Manter no chat apenas avisos compactos de quota/expiração quando relevantes.

Condições de sucesso

Verificação do slice

  • /subscription mostra estado de subscrição e checkout mock.
  • Subscritores continuam sem anúncios quando a regra assim define.
  • Aviso de expiração continua visível quando falta menos de uma semana.
  • O chat deixa de conter blocos permanentes de subscrição.
Refinamento

Direcção fechada

  • Criar /subscription como página própria para estado, plano trimestral e checkout mock.
  • Adicionar link de subscrição ao drawer, agora que a rota existe.
  • Extrair autenticação a pedido para AuthModal, reutilizado pelo chat e pela página de subscrição.
  • Deixar o chat sem painel permanente de facturação; manter apenas publicidade e aviso compacto de expiração.
Grill

Decisões bloqueadas

  • Sem pagamentos reais neste slice; os métodos continuam a usar o checkout mock existente.
  • O chat continua a consultar /api/billing/status apenas para regras de anúncios e aviso de expiração.
  • O histórico permanece no drawer e não é misturado com a página de subscrição.
  • O contrato backend de billing, quotas, webhooks e autenticação não muda.
Testes

  • tests/billing-ui.acceptance.test.ts passou a exigir checkout em /subscription e não no chat.

Verificação

  • Chrome DevTools confirmou /subscription, link no drawer, modal de login a pedido e consola sem erros.
Exclusões

O que não entra

  • Não integrar Appy Pay, Stripe/VISA ou pagamentos reais.
  • Não mudar limites de quota.
  • Não alterar o contrato de webhook.
  • Não redesenhar admin neste slice.
