Slice 23Login dev — refinado e grelhado

Ideia

Entrar sem OTP em dev

Adicionar uma superfície segura para autenticação local por contactos permitidos.

Origem

Decks aprovadas

  • docs/specs/brainstorm-dev-auth-login.html
  • docs/specs/dev-auth-login-architecture.html

Âmbito

Incluído

  • Variáveis UJIMU_DEV_AUTH_ENABLED e UJIMU_DEV_USER_CONTACTS.
  • Endpoint dev-only para estado e login.
  • Criação/reutilização de utilizador e identidade verificada.
  • Botão dev no modal de login.
  • Testes de segurança para produção e passkeys.

Decisões grelhadas

Guardas finais

  • O modo dev nunca funciona em NODE_ENV=production.
  • A allowlist não é enviada para o browser.
  • Admin continua a depender de UJIMU_ADMIN_CONTACTS.
  • Sessão dev não é OTP recente e não desbloqueia passkeys.

Zonas prováveis

Implementação

  • server/utils/auth/dev-login.ts
  • server/api/auth/dev-login.get.ts e .post.ts
  • components/AuthModal.vue
  • .env.sample
  • Testes de auth e UI.

Sucesso

Condições

  • Contacto allowlisted entra sem OTP em dev.
  • Contacto admin allowlisted ganha acesso admin se também estiver em UJIMU_ADMIN_CONTACTS.
  • Contacto não allowlisted é recusado.
  • Produção bloqueia o endpoint.
  • Suite, typecheck, build e audit passam.

Exclusões

Não fazer

  • Não alterar quotas, billing, chat, ingestion ou permissões admin.
  • Não adicionar passwords.
  • Não enviar OTPs falsos ao UI.
  • Não criar fluxo de produção sem OTP/passkey.
