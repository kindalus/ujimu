Slice 37

Logs auditáveis de sessões de agente

Fundação comum para registar sessões de inicialização, conversão e ingestão em formato legível e global.

Origem

Decks aprovados

  • Brainstorm: ../brainstorm-agent-managed-specialist-wiki.html.
  • Arquitectura: ../agent-managed-specialist-wiki-architecture.html.
  • Aplica-se AGENTS.md do projecto e o processo Zafir.
  • Antes de tocar no SDK Pi, confirmar documentação oficial Pi.
Ideia

Auditoria antes da autonomia

  • Criar escritor de logs globais em <UJIMU_DATA_DIR>/logs/agents/.
  • Usar nomes ISO seguros: YYYY-MM-DDTHH-mm-ss-SSSZ-[id]-[task].log.
  • Normalizar eventos do agente para leitura humana.
  • Marcar raciocínio oculto/encriptado quando não estiver legível.
Escopo

Fundação reutilizável

  • API interna para abrir, escrever e fechar logs de sessão.
  • Sanitização de dados sensíveis em texto, tools e payloads.
  • Formatação de mensagens, chamadas a tools e encerramento da sessão.
  • Integrar só na criação de sessões Pi já existentes para conversão e ingestão.
Zonas prováveis

Implementação esperada

  • server/utils/pi/session.ts — ponto de captura de eventos, após validar API oficial.
  • server/utils/agents/logs.ts — novo módulo de logging auditável.
  • server/utils/config.ts — derivação de directório de logs se necessário.
  • tests/*agent*log*.test.ts — nomes, sanitização, formatação.
Exclusões

Não fazer neste slice

  • Não implementar inicialização transaccional.
  • Não alterar prompts de ingestão ou chat.
  • Não mexer no ingest/state.json.
  • Não criar UI para ver logs.
Sucesso

Condições verificáveis

  • Uma sessão simulada gera log global com nome correcto.
  • Eventos sensíveis são redigidos.
  • Raciocínio não legível aparece como oculto/encriptado.
  • Testes e typecheck passam sem alterar comportamento existente.
Refinação

Direcção escolhida

  • Resolver primeiro a observabilidade mínima antes da inicialização autónoma.
  • Manter logs como ficheiros globais simples, sem base de dados nem UI neste slice.
  • Registar texto completo do assistente, não text_delta incremental.
  • Usar o ponto comum createUjimuPiSession para que conversão e ingestão herdem a fundação.
Grill

Decisões fechadas

  • Nome de ficheiro: YYYY-MM-DDTHH-mm-ss-SSSZ-[specialist_id]-[task].log.
  • Eventos de texto do assistente são agregados em assistant_text com redacção de e-mail, tokens, chaves e números.
  • thinking_delta e toolcall_delta não são registados para evitar ruído.
  • tool_call regista argumentos; tool_result regista resposta redigida e truncada quando necessário.
Fonte Pi

API verificada

  • Confirmada a documentação oficial do SDK Pi em docs/sdk.md.
  • O SDK expõe session.subscribe(listener) para eventos.
  • Eventos relevantes: message_update, tool_execution_start, tool_execution_update, tool_execution_end, agent_start e agent_end.
  • A integração mantém session.prompt(), session.abort() e session.dispose() existentes.
Testes

RED → GREEN

  • Teste: tests/agent-session-logs.acceptance.test.ts.
  • RED inicial confirmado quando server/utils/agents/logs.ts ainda não existia.
  • RED de correcção confirmou logs com text_delta, sem argumentos nem conteúdo de tools.
  • GREEN confirma texto completo, argumentos, respostas de tools, redacção e ausência de deltas ruidosos.
Implementação

Concluída

  • Novo módulo server/utils/agents/logs.ts para criar, escrever e fechar logs.
  • server/utils/pi/session.ts anexa o logger por session.subscribe quando solicitado.
  • Conversão, ingestão e inicialização Pi passam specialistId e fecham o log com estado final.
  • O formato agora privilegia conteúdo útil: assistant_text, tool_call e tool_result.
