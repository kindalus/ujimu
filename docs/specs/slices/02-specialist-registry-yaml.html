Specialist registry & YAML configuration

Load, validate, reload, create, and delete specialists represented by directories on disk.

specialist.yaml LLM Wiki presets registry reload
Idea

A specialist is a directory contract.

The application should discover specialists from disk and expose a validated registry to the rest of the system.

Directory shape

The file system is part of the product model.

~/.local/share/ujimu/
  db/
    ujimu.sqlite
  specialties/
    iva/
      specialist.yaml
      raw/
      wiki/
      ingest/state.json
YAML contract

Minimal configuration for the MVP.

id: iva
name: "Legislação de IVA"
description: "Especialista sobre legislação de IVA."
wiki_type: legislation-regulatory
system_prompt: "Answer only from this specialist wiki."
citations_required: true
streaming_enabled: true
Allowed wiki types

The type must map to an LLM Wiki preset.

research-project book-companion personal-journal-backed business-team-knowledge help-desk-faq-customer-support engineering-internal-technical-documentation legislation-regulatory custom-domain

Validation

Bad specialist data must fail safely.

  • IDs are stable lowercase slugs and must match the specialist directory name.
  • Unknown wiki_type values are rejected.
  • Description is required; visibility is omitted because MVP wikis are public by specialty.
  • Missing required folders are created only during controlled create operations.
  • Invalid YAML prevents that specialist from loading but does not crash the whole app.
  • System prompts are stored as specialist configuration, not as global app rules.
Deletion

Admin deletion is destructive in the MVP.

  • Deleting a specialist removes it from the registry.
  • Customer conversation history for that specialist is permanently deleted.
  • The deleted specialist is no longer selectable in the UI or usable by chat APIs.
  • Implementation should make destructive deletion explicit in the admin flow.
  • This slice implements service-layer deletion; the full admin UI comes later.

Success conditions

What must be true when the slice is done.

  • A valid specialist folder appears in the runtime registry after app start.
  • Invalid YAML or unsupported wiki type is reported without taking down the app.
  • A manual reload refreshes the registry from disk.
  • Controlled service-layer creation produces the expected folder structure and YAML.
  • The public listing endpoint exposes only safe specialist metadata.
  • Deleting a specialist removes associated histories and prevents further consultation.
