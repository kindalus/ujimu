Slice 13

Three Pi agent pipeline

Separate source conversion, wiki ingestion, and user consultation into distinct Pi-backed sessions with isolated prompts, model selection, and tool policy.

conversion ingestion consultation project-local .pi
Brainstorm outcome

The pipeline becomes explicit.

Raw files no longer flow directly into wiki ingestion. Every source that reaches ingestion is Markdown, and the conversion step is owned by a dedicated Pi agent.

Architecture revisit

General architecture review is deferred.

  • This slice is not considered affected by legislation or regulatory material.
  • The current Nuxt, SQLite, specialist directory, and Pi SDK architecture remains the base.
  • The change is scoped to the Pi source pipeline and project-local Pi configuration.
  • A broader architecture deck can be revisited later if the agent pipeline expands beyond this scope.
Agent roles

Three sessions, three responsibilities.

ConversionTurns uploaded original files into generated Markdown sources under raw/.
IngestionReads Markdown sources only and maintains the specialist wiki with traceability.
ConsultationAnswers user questions from the selected specialist wiki with citations.
Source naming

Conversion output keeps the original extension.

raw/lei.pdf   → raw/lei.pdf.md
raw/lei.docx  → raw/lei.docx.md
raw/lei.html  → raw/lei.html.md
raw/lei.htm   → raw/lei.htm.md
raw/lei.txt   → raw/lei.txt.md
raw/lei.csv   → raw/lei.csv.md
raw/lei.xlsx  → raw/lei.xlsx.md
The output path is deterministic: append .md to the original raw relative path. This avoids collisions between files with the same base name but different original formats.
Direct Markdown upload

Admin-provided Markdown is renamed as original.

upload: lei.md
stored: raw/lei.original.md
  • Direct Markdown uploads are treated as already-normalized source originals.
  • The system must not create lei.md.md.
  • If raw/lei.original.md already exists, the upload is rejected as a duplicate.
  • Ingestion uses lei.original.md like any other Markdown ingestion source.
Generated artefacts

Converted Markdown is not admin-owned prose.

  • Converted .md files are generated artefacts.
  • If the original file changes, its generated Markdown is overwritten.
  • If the original has not changed and Markdown exists, conversion is skipped.
  • Manual edits to generated Markdown are not protected from overwrite after an original change.
Formats

The MVP accepts common source formats.

  • Conversion candidates: PDF, TXT, DOCX, HTML/HTM, CSV, and XLSX.
  • Scanned PDFs and OCR remain out of scope.
  • CSV/XLSX conversion should preserve tabular content faithfully; XLSX sheet names become headings.
  • The conversion agent must not silently summarize tabular sources.
  • Generated Markdown is capped by UJIMU_PI_CONVERSION_MAX_MARKDOWN_BYTES, default 1 MiB.
  • PDF conversion should structure Markdown as well as possible while retaining as much information as possible.
  • If content cannot be extracted safely or output is too large, conversion fails and ingestion does not run.
Tools boundary

No new Pi tools are introduced in this slice.

  • The slice does not add custom extractors or new tool capabilities.
  • Agent skills are instructions, not capabilities.
  • Allowed tools are enforced in code when creating each Pi SDK session.
  • bash remains disabled by default.
The existing file tools remain the boundary: read, write, edit, grep, find, and ls. Consultation should use read/search only.

Secrets

Auth is local or secret-managed.

  • .pi/auth.json must not be committed.
  • .pi/auth.json.sample documents safe example credentials and provider shapes.
  • .pi/settings.json defaults to openrouter/moonshotai/kimi-k2.6 with medium thinking.
  • .pi/models.json is a minimal custom-provider placeholder.
  • If the default lacks auth, fail clearly instead of silently selecting another model.
  • Conversion runs create safe admin audit events; consultation avoids new prompt/answer operational logs.
  • Automated tests use fake Pi adapters; real Pi is covered by a documented manual smoke path.
  • Production should mount credentials as secrets or use environment variables where possible.
  • The implementation should update ignore rules so the real auth file stays out of Git.
Model selection

Conversion and ingestion can override the default model.

  • Consultation uses the default model specified by the project-local .pi configuration.
  • Conversion can use a provider/model/thinking override from environment variables.
  • Ingestion can use a separate provider/model/thinking override from environment variables.
  • If an override is absent, the agent falls back to the project-local default.

Traceability

Every answer must trace back through the pipeline.

  • Conversion state links original raw path to generated Markdown path and checksums.
  • Ingestion state records the Markdown source used by the ingestion agent.
  • Citation metadata preserves the original source identity shown to users.
  • Analytics and chat history must not become grounding sources.
Locked decision

Conversion state stays with ingestion state.

  • Use the existing per-specialist ingest/state.json as the canonical source-pipeline state file.
  • Do not create a separate conversion/state.json in this slice.
  • The schema should distinguish conversion status from ingestion status.
  • Admin display, startup detection, reload, and manual actions read one state file.
Locked decision

State records are keyed by the original upload.

  • Use one source record per original uploaded file, not per generated Markdown artefact.
  • Converted records keep raw_path as the original path and store markdown_path in conversion metadata.
  • Ingestion metadata stores the Markdown path actually used by the ingestion agent.
  • Direct Markdown uploads are tracked as *.original.md with conversion marked not required.
Locked decision

State separates conversion from ingestion.

conversion.status:
  not_required | pending | processing | converted | failed

ingestion.status:
  blocked | pending | processing | ingested | failed
  • Use nested conversion and ingestion objects.
  • A conversion failure blocks ingestion for that source.
  • Admin UI can render two explicit pipeline stages.
Locked decision

Conversion is manual, not upload-time work.

Upload
→
Reload / detect
→
Run conversion
→
Run ingestion
  • Upload should not silently invoke Pi.
  • Reload detects pending state but does not run heavy agent work.
  • Admins explicitly trigger conversion and ingestion.
Locked decision

Ingestion skips sources that are not ready.

  • Ingestion processes only Markdown sources whose conversion stage is ready.
  • Sources with pending or failed conversion are skipped, not converted implicitly.
  • The API should return ingested and skipped counts with safe skipped reasons.
  • Example reasons: conversion_pending and conversion_failed.
Locked decision

Project-local llm-wiki controls ingestion.

  • Copy the current llm-wiki skill into .pi/skills/llm-wiki.
  • Add a minimal Ujimu override: ingest only Markdown files under raw/.
  • Non-Markdown raw files are conversion inputs and must not be ingested directly.
  • The project-local copy must win any skill-name collision with global llm-wiki.
Locked decision

Pi sessions use the Ujimu agent directory.

  • Resolve agentDir from UJIMU_PI_AGENT_DIR when set.
  • Fallback to the project-root .pi directory.
  • Pass the resolved agentDir explicitly to Pi SDK setup.
  • All three agents use project-local settings, models, auth convention, and skills.
Locked decision

Model overrides are all-or-default.

  • Use an override only when both provider and model are set for that role.
  • If neither is set, use the default from .pi/settings.json.
  • If only one is set, fail with a configuration error.
  • If the model is missing or unauthenticated, fail before starting the Pi session.
Locked decision

Each Pi role is enabled independently.

UJIMU_PI_CONVERSION_ENABLED=true
UJIMU_PI_INGESTION_ENABLED=true
UJIMU_PI_CHAT_ENABLED=true
  • Disabled roles fail safely without starting Pi sessions.
  • Admin conversion and ingestion can be enabled before user-facing chat.
  • Existing ingestion and chat flags remain compatible.
Locked decision

Generated Markdown is not scanned as a source.

  • *.pdf.md, *.docx.md, *.html.md, *.htm.md, *.txt.md, *.csv.md, and *.xlsx.md never create independent source records.
  • They are discovered through the original source record's conversion metadata.
  • *.original.md does create a source record because it is an uploaded normalized original.
Locked decision

Changed originals invalidate downstream state.

  • If an original checksum changes, mark conversion as pending.
  • Mark ingestion as blocked until the new Markdown is converted.
  • Do not expose stale ingested evidence for changed originals.
  • Chat ignores the source until refreshed conversion and ingestion complete.
Locked decision

Failed conversion keeps old Markdown but blocks ingestion.

  • Do not delete an existing generated Markdown file when a later conversion fails.
  • Keep the file for diagnosis and Git diffability.
  • The state remains failed/blocked, so ingestion cannot use the stale artefact.
  • Ingestion trusts state, not file existence alone.
Locked decision

Real Pi consultation ships in this slice.

  • The consultation agent is not just scaffolding or a placeholder.
  • Implement a real Pi SDK chat runner behind UJIMU_PI_CHAT_ENABLED=true.
  • When disabled, misconfigured, ungrounded, or missing valid citations, fail safely.
  • The runner uses the project-local default Pi model and read/search-only access.
Locked decision

Consultation streams structured NDJSON.

{"type":"citations","citations":[{"sourceFile":"raw/lei.pdf","articleRefs":["Artigo 1.º"]}]}
{"type":"delta","text":"..."}
{"type":"done"}
  • The Pi-backed agent emits machine-readable events, not free-form source text.
  • The first forwarded answer text must come after a valid citations event.
  • Free text before citations is buffered, never shown immediately.
  • The pre-citation buffer is capped at 16 KB.
  • Accepted event types: citations, delta, done, and error.
  • If valid citations arrive, buffered text may be released as initial answer text.
  • If citations never validate, an unknown event appears, or the buffer limit is exceeded, discard the buffer and trigger fallback.
  • Consultation is read-only: no derived pages are written during user chat.
  • Conversion may write only its deterministic Markdown target under raw/.
  • Conversion output must exist, have ≥20 non-whitespace characters, and be checksummed.
  • Direct Markdown uploads become *.original.md, skip conversion, and go straight to pending ingestion.
  • Manual conversion endpoint: POST /api/admin/specialists/:id/conversion/run.
  • Conversion run retries pending and failed sources, skipping converted/not-required sources.
  • Stale conversion or ingestion processing work older than UJIMU_PI_PIPELINE_STALE_PROCESSING_MINUTES is retryable; default 30 minutes.
  • Reingestion reconciles existing wiki pages; it does not delete or duplicate pages by default.
  • User-facing citations point to the original upload path, not generated Markdown artefacts.
  • The consultation prompt includes the backend-computed allowlist of usable citation evidence.
  • The backend validates returned citations against the same allowlist.
  • Consultation answers from wiki/, not by reading raw/ at answer time.

Success conditions

The slice is done when the pipeline is observable and safe.

  • An admin can upload PDF/TXT/DOCX/HTML/HTM/CSV/XLSX and the system records a conversion target ending in .md.
  • TXT and any extractable source are converted to Markdown before ingestion.
  • Direct Markdown upload is stored as .original.md and duplicate originals are rejected.
  • Ingestion reads only Markdown sources and preserves original-source traceability.
  • The project-local llm-wiki skill wins collisions and enforces Markdown-only raw ingestion.
  • Real Pi-backed consultation answers from the wiki through validated structured NDJSON events with citations produced from the converted pipeline.
Explicit exclusions

Keep this slice focused.

  • No OCR for scanned PDFs.
  • No new Pi tools or custom extraction tools.
  • No broad architecture redesign.
  • No real payment, OTP, or deployment changes.
  • No automatic wiki content creation from analytics signals.
