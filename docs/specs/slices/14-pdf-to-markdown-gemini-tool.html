Ferramenta PDF para Markdown via Gemini

Slice derivada do brainstorming ../pdf-to-markdown-tool-brainstorming.html.

Ideia

Converter PDFs para Markdown por uma ferramenta Pi controlada

A slice adiciona uma ferramenta project-local que chama o Gemini CLI para produzir Markdown fiel a partir de PDFs, mantendo a convenção raw/ficheiro.pdf.md.

Âmbito

O que entra nesta slice

  • Script Bash pdf_to_markdown.sh local ao projecto.
  • O alvo de saída preserva exactamente o nome da fonte e acrescenta .md, incluindo extensões como .PDF.
  • Ferramenta disponível apenas na sessão do agente de conversão, para fontes PDF, e não exposta aos agentes de ingestão, consulta ou outras sessões Pi.
  • Instruções Gemini para conversão fiel, sem resumo e com nome de saída determinístico.
  • Restrição a PDFs dentro de raw/ da especialidade actual.
  • Documentação da dependência operacional no Gemini CLI.
  • Preservação do comportamento actual para fontes que não sejam PDF.

Decisões iniciais

Base aceite antes do grill-me

Legislação

A funcionalidade não é governada nem afectada por legislação.

Arquitectura

Revisão arquitectónica deferida; usar a arquitectura existente.

Dependência

gemini torna-se uma dependência operacional documentada.

Escopo do agente

A ferramenta é chamada pelo agente de conversão quando a fonte é PDF e não fica disponível para outros agentes.

Escrita do ficheiro

O script captura/normaliza a saída do Gemini e escreve o Markdown final, em vez de depender do Gemini para escrever directamente.

Limite de caminho

A ferramenta só aceita PDFs localizados em raw/ da especialidade actual.

Timeout inicial

A chamada ao Gemini CLI deve ter timeout inicial de 10 minutos por PDF.

Tamanho máximo

O limite de tamanho do Markdown deve reutilizar a validação existente do pipeline, sem segundo limite próprio no script.

Reprocessamento

Se o Markdown alvo já existir, a ferramenta pode sobrescrevê-lo quando a conversão estiver a ser reprocessada pelo pipeline.

Saída do Gemini

O Gemini deve devolver apenas Markdown em stdout; o script escreve o ficheiro final.

Formatos não PDF

CSV, XLSX, HTML, TXT e outros formatos continuam no fluxo actual, sem usar esta ferramenta.

Disponibilidade Pi

A criação de sessões Pi deve aceitar ferramentas extra por tarefa e injectar a ferramenta pdf_to_markdown apenas quando task === "conversion".

Prompt PDF

Para fontes PDF, o prompt do agente de conversão deve obrigar o uso de pdf_to_markdown e depois terminar.

Falha PDF

Se pdf_to_markdown falhar, o agente não tenta converter manualmente com ferramentas de ficheiro; a conversão falha claramente.

CLI indisponível

Quando gemini não existir no PATH, o estado de conversão deve usar GEMINI_CLI_UNAVAILABLE.

Chave Gemini

Em operação e smoke tests manuais, além do CLI instalado, GEMINI_API_KEY deve estar definida.

Chave em falta

GEMINI_API_KEY ausente deve falhar antes de chamar o CLI com erro GEMINI_API_KEY_MISSING.

Validação dupla

A extensão Pi valida GEMINI_API_KEY para erro estruturado; o script também valida para execução manual/smoke test.

Erros do script

O script escreve erros prefixados em stderr, como GEMINI_API_KEY_MISSING: ...; a extensão converte-os em erro estruturado.

Normalização de fence

Se o Gemini devolver uma única fence exterior ```markdown, o script remove só esse invólucro, preservando fences internas.

Formato do comando

O PDF é passado como último argumento no formato gemini -y -p "<instruções>" raw/ficheiro.pdf.

Timeout

O script usa timeout 600s; se timeout não existir, falha com TIMEOUT_COMMAND_UNAVAILABLE em vez de correr sem limite.

Ambiente de execução

Não se adiciona dependência operacional macOS/coreutils; produção corre em containers que devem fornecer timeout.

Autenticação Gemini

Falhas de autenticação/configuração do Gemini CLI devem usar GEMINI_CLI_AUTH_FAILED; restantes falhas usam GEMINI_CONVERSION_FAILED.

Escrita atómica

O script escreve para ficheiro temporário e faz rename atómico para .pdf.md apenas após validação básica.

Limpeza temporária

O Bash usa trap para remover ficheiros temporários em falha/interrupção, excepto após rename bem-sucedido.

Validação mínima

Antes do rename, a saída deve ter pelo menos 20 caracteres não-brancos; o limite máximo continua no pipeline.

Argumento de caminho

A ferramenta aceita apenas caminho relativo iniciado por raw/; caminhos absolutos são rejeitados.

Extensão PDF

A ferramenta aceita apenas ficheiros com extensão .pdf de forma case-insensitive, antes de chamar Gemini.

Realpath

O PDF e o alvo .pdf.md devem resolver por realpath para dentro de raw/; .. e symlink escape são rejeitados.

Ficheiro regular

Antes de chamar Gemini, a entrada deve existir e ser ficheiro regular resolvido dentro de raw/.

Input inválido

Caminho fora de raw/, não-PDF ou ficheiro inexistente usam o código INVALID_PDF_INPUT, com detalhe na mensagem.

Raiz da especialidade

O script assume que é executado com cwd igual à raiz da especialidade e não recebe essa raiz como argumento.

Resultado da ferramenta

A ferramenta devolve apenas metadados estruturados, como status, markdownPath e bytes, nunca o Markdown completo.

JSON de sucesso

Em sucesso, o script imprime JSON em stdout; a extensão valida/normaliza antes de devolver ao agente.

Output inválido

Se o script devolver JSON inválido em sucesso, a extensão falha com PDF_TOOL_INVALID_OUTPUT.

Logs seguros

A extensão não regista prompt completo, stdout completo, nem conteúdo Markdown; só metadados e erros curtos.

Segredos

GEMINI_API_KEY é segredo sensível; erros, stdout, stderr capturado e logs devem ser sanitizados para nunca expor a chave.

Gestão da chave

A documentação deve exigir GEMINI_API_KEY em variável de ambiente/secret manager, nunca em .pi/settings.json, prompts ou ficheiros versionados.

Prompt Gemini

O prompt inclui o caminho final esperado, mas instrui o Gemini a não escrever ficheiros e a devolver apenas Markdown em stdout.

Fluxo Pi

O agente de conversão continua no fluxo: o runner disponibiliza a ferramenta e o prompt obriga a sua chamada para PDFs.

Zonas de implementação

Ficheiros prováveis

Script

.pi/tools/pdf_to_markdown.sh

Extensão

.pi/extensions/pdf-to-markdown-tool.ts

Documentação

docs/operations.md e/ou documentação de desenvolvimento.

Testes

Testes de aceitação com gemini e timeout falsos no PATH; Gemini real fica para smoke test operacional/manual.

Teste de escopo

Os testes devem confirmar que só a sessão conversion recebe pdf_to_markdown; ingestion e chat não recebem.

Teste de segredo

Testes com GEMINI_API_KEY falsa devem confirmar que a chave não aparece em erros ou resultados devolvidos.

Condições de sucesso

Critérios observáveis

  • A ferramenta Pi aceita um PDF válido dentro de raw/ e calcula o alvo .pdf.md.
  • O comando Gemini inclui instruções de conversão e a nomenclatura final.
  • O script escreve o ficheiro final .pdf.md depois de capturar e validar a saída do Gemini.
  • A chamada ao Gemini CLI respeita um timeout inicial de 10 minutos por PDF.
  • O tamanho máximo do Markdown é validado pelo limite existente do pipeline, evitando regras duplicadas no script.
  • Se raw/ficheiro.pdf.md já existir durante reprocessamento, a ferramenta sobrescreve o alvo de forma idempotente.
  • O Gemini é instruído a devolver apenas Markdown em stdout, sem tentar escrever ficheiros.
  • Fontes PDF obrigam o agente de conversão a usar pdf_to_markdown; fontes não PDF continuam no comportamento actual.
  • Se a ferramenta PDF falhar, a conversão falha imediatamente sem tentativa manual pelas ferramentas de ficheiro.
  • Falhas do Gemini CLI são reportadas claramente e não fingem sucesso.
  • Gemini CLI ausente ou fora do PATH produz erro GEMINI_CLI_UNAVAILABLE.
  • Smoke tests manuais e operação validam que GEMINI_API_KEY está definida, além de gemini estar instalado.
  • GEMINI_API_KEY ausente produz GEMINI_API_KEY_MISSING antes de qualquer chamada ao CLI.
  • A extensão Pi e o script Bash validam ambos GEMINI_API_KEY.
  • Erros do script usam prefixos estáveis em stderr para a extensão Pi devolver erro estruturado.
  • Uma única fence Markdown exterior é removida; fences internas legítimas são preservadas.
  • O comando Gemini usa o formato gemini -y -p "<instruções>" raw/ficheiro.pdf, com o PDF como último argumento.
  • O timeout é aplicado com timeout 600s; ausência do comando produz TIMEOUT_COMMAND_UNAVAILABLE.
  • Não há dependência operacional em macOS/coreutils; operação alvo é containerizada e deve incluir timeout.
  • Falhas de autenticação/configuração produzem GEMINI_CLI_AUTH_FAILED; restantes falhas Gemini produzem GEMINI_CONVERSION_FAILED.
  • O ficheiro final é escrito via temporário e rename atómico, evitando Markdown parcial.
  • Ficheiros temporários são removidos em falha/interrupção através de trap.
  • Antes do rename, o script valida pelo menos 20 caracteres não-brancos; o limite máximo fica no pipeline.
  • A ferramenta rejeita caminhos absolutos ou fora de raw/.
  • A entrada deve terminar em .pdf, case-insensitive, antes de qualquer chamada ao Gemini.
  • O alvo preserva a grafia original do caminho e acrescenta .md, por exemplo raw/Documento.PDF.md.
  • A validação por realpath rejeita .., symlinks e qualquer resolução que escape de raw/.
  • A entrada deve existir e ser ficheiro regular antes de chamar Gemini.
  • Inputs inválidos usam código único INVALID_PDF_INPUT, com detalhe na mensagem.
  • O script assume cwd na raiz da especialidade; a interface aceita apenas o caminho relativo do PDF.
  • A ferramenta devolve metadados estruturados sem incluir o conteúdo Markdown completo.
  • Em sucesso, o script imprime JSON com status, markdownPath e bytes; a extensão valida essa resposta.
  • JSON inválido do script em caminho de sucesso produz erro PDF_TOOL_INVALID_OUTPUT.
  • Logs e resultados evitam prompt completo, stdout completo e conteúdo Markdown.
  • GEMINI_API_KEY é tratada como segredo e removida de erros, stdout, stderr capturado e logs.
  • A documentação proíbe colocar GEMINI_API_KEY em .pi/settings.json, prompts ou ficheiros versionados.
  • O comando Gemini inclui o caminho final esperado nas instruções, mas proíbe escrita directa de ficheiros.
  • O runner não contorna o agente Pi; disponibiliza a ferramenta apenas à sessão de conversão e o prompt exige a chamada em PDFs.
  • Testes de aceitação usam gemini e timeout falsos no PATH; não invocam credenciais ou serviços reais.
  • A ferramenta Pi exposta ao agente de conversão chama-se exactamente pdf_to_markdown.
  • Testes de escopo confirmam que pdf_to_markdown só está disponível para conversion, nunca para ingestion ou chat.
  • Testes de sanitização confirmam que uma GEMINI_API_KEY falsa não aparece em mensagens de erro ou resultados.
  • A documentação operacional inclui smoke test manual com Gemini real, exigindo gemini no PATH e GEMINI_API_KEY definida.
  • A dependência gemini fica documentada para operação e desenvolvimento.

Exclusões

O que fica fora

  • Ingestão automática depois da conversão.
  • Garantia própria de OCR para PDFs digitalizados.
  • Execução arbitrária de comandos de shell.
  • Exposição da ferramenta ao agente de ingestão, ao agente de consulta ou a sessões Pi genéricas.
  • Reescrita ampla do pipeline de ingestão/conversão já existente.
