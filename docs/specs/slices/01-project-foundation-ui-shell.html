Slice 1

Project foundation & UI shell

Create the smallest runnable Nuxt product shell that future slices can extend without reworking the platform.

Nuxt Nuxt UI TypeScript npm SQLite UI shell
Idea

Start with a working product frame.

This slice proves the app can run, load configuration, initialise SQLite, and render the core chat-like layout before specialist logic exists.

Decisions

Locked foundations

StackNuxt with TypeScript, Nuxt UI, npm, SQLite, and no ORM.
Copy rulesImplementation docs stay in English; UI text is pt-PT pre-1990.
Data rootSpecialist data lives under UJIMU_DATA_DIR; SQLite lives inside UJIMU_DATA_DIR/db.
Scope

In scope vs. out of scope

In scopeNuxt app, Nuxt UI module/theme, routing shell, runtime config, SQLite connection, migration runner, placeholder layouts.
Out of scopeReal chat answers, authentication, billing, ingestion, quotas, and admin mutations.
Design constraintBlack and white base with Angola-flag yellow accent; clean chat-product feel.
UI frame

The first screen should already feel like Ujimu.

  • Landing area with a specialist selector placeholder.
  • Chat workspace placeholder using Nuxt UI components with empty-state copy in pt-PT pre-1990.
  • AI notice area prepared for later specialist-specific disclaimers.
  • Advertising slots reserved without loading real adverts.
Runtime config

Configuration is explicit from day one.

UJIMU_DATA_DIR=~/.local/share/ujimu
UJIMU_DB_PATH=$UJIMU_DATA_DIR/db/ujimu.sqlite
NUXT_PUBLIC_APP_NAME=Ujimu
SQLite base

No ORM, but not ad-hoc SQL everywhere.

  • Create a small server-side database module for opening SQLite connections under data_dir/db.
  • Add a migration mechanism based on ordered SQL files or embedded migration definitions.
  • Create a schema_migrations table before feature tables exist.
  • Keep all database access server-only.

Success conditions

What must be true when the slice is done.

  • A developer can install dependencies with npm and run the app locally.
  • The default page renders the Ujimu shell with Nuxt UI components, specialist selector, chat area, AI notice placeholder, and ad placeholders.
  • Runtime config resolves UJIMU_DATA_DIR, including the default path when no env var is set.
  • SQLite database files are created under UJIMU_DATA_DIR/db by default.
  • SQLite initialises and records applied migrations without using an ORM.
  • No user-facing UI copy violates the pt-PT pre-1990 rule.
Risks

Keep the foundation boring.

  • Avoid building real features in the shell slice.
  • Avoid a custom design system too early; use reusable primitives only where they are immediately needed.
  • Do not let client code access filesystem paths or SQLite directly.
