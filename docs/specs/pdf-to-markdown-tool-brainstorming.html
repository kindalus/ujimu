Ferramenta PDF para Markdown via Gemini CLI

Conceito de ferramenta Pi local ao projecto para converter fontes PDF carregadas em artefactos Markdown determinísticos.

Não governada por legislação Slice de implementação futura Dependência: gemini CLI

Enquadramento do problema

Como poderemos converter PDFs em Markdown fiel sem alargar as capacidades das ferramentas de ficheiros do Pi?

O pipeline de ingestão do Ujimu privilegia Markdown. A conversão de PDF é um bloqueio prático quando as fontes só estão disponíveis em PDF.

Direcção confirmada

Expor pdf_to_markdown.sh como ferramenta de projecto chamável pelo Pi

Script

pdf_to_markdown.sh recebe o caminho de um PDF e chama o Gemini CLI com instruções estritas de conversão.

Formato do comando

gemini -y -p "<instructions + output filename>" ficheiro.pdf

Convenção de saída

raw/document.pdf passa a raw/document.pdf.md.

Integração com o Pi

Usar uma extensão Pi para expor uma ferramenta nomeada em vez de execução arbitrária de shell.

Variações consideradas

Porque esta forma é preferida

Apenas bash directo

Mais simples, mas menos controlado e menos descobrível pelo Pi.

Extensão Pi + script

Melhor equilíbrio: script fixo, argumentos tipados e fronteira clara da ferramenta.

Conversor completo em Node

Mais nativo, mas duplica a capacidade PDF do Gemini e aumenta o custo.

Âmbito MVP

Menor versão útil

  • Criar um script Bash local ao projecto chamado pdf_to_markdown.sh.
  • Criar uma extensão Pi local ao projecto que registe uma ferramenta para executar esse script.
  • Exigir Markdown fiel, sem resumo, preservação da língua original e caminho de saída determinístico.
  • Documentar instalação, autenticação, configuração e modos de falha operacional do Gemini CLI.

Decisão de dependência

Gemini CLI torna-se uma dependência operacional

Documentação necessária

Registar a dependência antes de considerar a implementação completa.

Expectativa em execução

gemini deve estar disponível no PATH e autenticado para uso não interactivo.

Modo de falha

CLI ausente ou em falha deixa a conversão falhada e a ingestão bloqueada.

Postura de segurança

Não expor segredos em prompts, logs ou resultados da ferramenta.

Pressupostos principais

Aquilo que assumimos como verdadeiro

  • O Gemini CLI consegue ler de forma fiável os PDFs-alvo usados pelos operadores do Ujimu.
  • A autenticação do CLI pode ser configurada com segurança no ambiente de execução.
  • O Markdown gerado pode ser restringido ao caminho de destino determinístico.
  • A dependência externa no CLI da Google é aceitável para esta funcionalidade.

Fora de âmbito

Exclusões explícitas

  • Sem garantia de OCR para PDFs digitalizados, salvo se o Gemini CLI os tratar na prática.
  • Sem ingestão automática após a conversão na primeira versão.
  • Sem reescrita ampla do pipeline de conversão Pi existente.
  • Sem ferramenta de execução arbitrária de comandos.

Perguntas em aberto

Perguntas antes de cortar a slice

  • A ferramenta deve ficar limitada às directorias raw/ das especialidades?
  • O Gemini deve escrever o ficheiro directamente, ou o script deve capturar stdout e escrever o ficheiro de destino?
  • Que timeout e tamanho máximo de Markdown deve o script impor?
  • Isto deve substituir a conversão de PDF ou começar como auxiliar manual/admin?
