Brainstorming encerrado · sem alteração persistente

Invocação global das três skills

Passar de “skill disponível” para “skill efectivamente lida e aplicada” em cada sessão Pi do Ujimu.

Evidência do teste

Disponível não significa usada

Carregadas no prompt

llm-wiki, research e unslop apareceram no XML de skills disponíveis.

Leituras efectivas

O DeepSeek leu a wiki, mas não abriu qualquer SKILL.md.

Resposta

A resposta estava correcta e citada, mas não há prova de aplicação das instruções completas das skills.

Problema

As descrições funcionam como índice; o conteúdo completo só entra quando o modelo usa read.

Objectivo

Como obrigar o uso sem esconder o custo?

Acrescentar uma instrução ao system prompt comum de todas as sessões: antes de executar a tarefa, abrir as três skills disponibilizadas pelo Ujimu e aplicar as respectivas instruções compatíveis com a tarefa.

Sucesso observável

No novo teste com openrouter/deepseek/deepseek-v4-flash, os tool calls devem incluir os três caminhos config/pi/skills/*/SKILL.md antes da resposta.

Direcções avaliadas

Três níveis de obrigação

A · Global e obrigatória

Usar appendSystemPromptOverride no loader. Todas as sessões lêem as três skills. Cumpre literalmente o pedido.

B · Apenas consultas

Alterar só o prompt de chat. Menor custo, mas inicialização e ingestão não recebem a regra global.

C · Conforme relevância

Forçar unslop e deixar as outras por gatilho. Mais eficiente, mas não garante o uso das três em cada teste.

Recomendação

Direcção A, se “global” significa realmente todas as tarefas Pi.

Riscos conhecidos

A obrigação tem efeitos laterais

Contexto e latência

Cada sessão passa a ler três ficheiros antes de trabalhar, mesmo quando duas skills não são relevantes.

research

Pede um agente de fundo que o runtime Ujimu não disponibiliza. A instrução global deve proibir a simulação dessa capacidade.

llm-wiki

Inclui manutenção da wiki. Em consultas, a regra deve manter a sessão em modo de leitura e evitar alterações.

unslop

É compatível com todas as respostas e melhora a redacção sem alterar a fonte de verdade.

Decisão confirmada

Teste isolado, sem ordem persistente

O objectivo é apenas comprovar se o agente consegue abrir as três skills quando recebe uma ordem explícita na própria consulta.

Não alterar

System prompt, prompts do produto, configuração das especialidades ou comportamento das sessões futuras.

Verificar

Os tool calls do teste devem mostrar a leitura de llm-wiki, research e unslop antes da resposta.
