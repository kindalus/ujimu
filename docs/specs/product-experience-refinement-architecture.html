Arquitectura aprovada · 2026-08-23

Extensões cirúrgicas, módulos actuais

Manter Nuxt, SQLite, NDJSON e sessões Pi. Acrescentar comportamento nos pontos onde a arquitectura já concentra cada responsabilidade.

Princípio

Sem nova camada transversal

  • Geometria e campos ficam no último CSS global carregado.
  • O drawer continua num único componente partilhado.
  • O endpoint de chat mantém um contrato único para perguntar, editar e refazer.
  • SQLite continua a resolver histórico, analytics e jobs.
  • O hard reset usa o worker recuperável existente, com um tipo de job próprio.
Controlos

Um contrato visual por papel

Acção

Pill, altura já aprovada e cursor pointer quando utilizável.

Ícone

Círculo com alvo mínimo de 2.75rem.

Estrutura

Cartões, opções e toggles conservam a sua geometria.

Campo

Input e textarea de formulário usam linha inferior; composer, OTP e select ficam isolados.

Drawer responsivo

O estado acessível segue o breakpoint

matchMedia(1024px)
├─ desktop no chat → drawer visível, não inert, sem trigger/scrim/fecho
└─ abaixo de desktop → comportamento temporário actual
  • Apenas o chat activa persistência no desktop.
  • O shell reserva 320px; perfil e administração não ganham uma segunda barra.
  • Trocas de breakpoint actualizam foco, aria-hidden e inert.
Refazer

Expressar intenção, não IDs internos

POST /api/chat { conversationId, question, regenerateLast: true }
→ validar propriedade e último turno
→ ramificar antes da última pergunta
→ executar o modelo
→ commit atómico ou rollback
  • Registados substituem o último par SQLite depois do sucesso.
  • Anónimos ramificam directamente a última entrada Pi.
  • Falha conserva resposta, sessão e histórico anteriores.
Título

Usar a chamada que já produz a resposta

modelo de chat → deltas + citações + {type:"title", title:"…"}
→ parser valida e limita a 80 caracteres
→ persistência usa título estruturado no primeiro turno
  • Sem segunda chamada no caminho normal.
  • Metadado malformado mantém o título provisório.
  • Uma operação controlada usa o mesmo contrato para corrigir os 13 registos pendentes, sem escrever conteúdo em logs.
Visitantes

Contar identidades ligadas, não somar categorias

eventos do mês
→ cookie ligado a conta em qualquer evento? usar user:<id>
→ cookie nunca ligado? usar visitor:<id>
→ COUNT DISTINCT da identidade canónica
  • O login no chat regista imediatamente a ligação cookie-conta.
  • Sem IP, fingerprint ou dados novos.
  • O total histórico pode diminuir quando um cookie anónimo fica ligado a uma conta.
Hard reset

Um job destrutivo com fronteira própria

confirmação admin → recusar job concorrente → status initializing
→ preservar raw/ → apagar restantes dados → recriar config
→ inicializar wiki → detectar raw como pending → awaiting_sources
  • Conversas, sessões Pi, perguntas analíticas e derivados desaparecem.
  • Auditoria e quotas globais permanecem.
  • Falha nunca apaga raw/.
Segurança e falhas

Cada módulo conserva o seu rollback

  • Output do modelo é validado antes de virar título.
  • Refazer usa o journal e o commit já usados pela edição.
  • Analytics não amplia recolha nem aceita estado do cliente como autoridade.
  • Hard reset exige administrador, confirmação exacta e ausência de job activo.
  • Alterações visuais preservam foco, alvos de 44px e auto-resize de cinco linhas.
Decisão

Arquitectura actual mantida

  • Nenhuma dependência nova.
  • Nenhum serviço externo novo.
  • Um campo opcional no pedido de chat para Refazer.
  • Um evento interno de título e um tipo de job para hard reset.
  • Queries e componentes existentes continuam a ser os pontos de teste.
