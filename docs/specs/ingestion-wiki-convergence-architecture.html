Convergência dentro da sessão de ingestão

Usar o ciclo de lint da skill existente, sem criar outro serviço nem alterar o manifesto.

Posição no fluxo

Verificar depois de integrar, antes do manifesto

converter → ingerir → actualizar índice e log
          → verificar → corrigir → verificar novamente
          → passagem limpa → escrever manifesto
Critério

Só problemas corrigíveis alimentam o ciclo

  • Conformidade OKF, linhagem, links, órfãos, duplicações, conteúdo obsoleto e coerência transversal.
  • Uma passagem limpa não encontra novo problema que as fontes actuais permitam corrigir.
  • Um conflito legítimo entre fontes é conhecimento a representar, não um erro a apagar.
  • Ambiguidade que requer confirmação interrompe a correcção desse ponto, não autoriza invenção.
Persistência

Sem mudar contratos de dados

  • Correcções permanecem em wiki/, wiki/index.md e wiki/log.md.
  • Problemas ligados a uma fonte entram no respectivo failed[] ou warnings.
  • Conflitos não resolvidos ficam explicitamente documentados no wiki e no log.
  • O manifesto conserva a versão 2 e a validação actual.
Implementação

Uma instrução partilhada por dois prompts

  • Definir um bloco de instruções de convergência no runner.
  • Inseri-lo no prompt batch e no prompt antigo de fonte única.
  • O teste de aceitação verifica o texto enviado à sessão normal.
  • Nenhum modelo, ferramenta, endpoint ou schema muda.
Prova

Contrato textual exacto

  • O prompt exige verificação e correcção antes do manifesto.
  • A condição de saída é uma passagem completa sem novo problema corrigível.
  • O prompt proíbe inventar consenso entre fontes.
  • Testes, typecheck e build fecham a alteração.
