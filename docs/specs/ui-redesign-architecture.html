Reformulação da UI do UjimuArquitectura — aprovada
Arquitectura

UI como aplicação de consulta

Desenhar a nova estrutura de interface antes de cortar slices: chat como superfície principal, navegação por drawer, fluxos de conta/subscrição separados e admin operacional.

Origem

Brainstorming aprovado

  • Deck de origem: docs/specs/brainstorm-ui-redesign.html.
  • Direcção: reformulação completa da UI, não apenas o chat público.
  • Regra: decks Zafir escritos em português europeu pré-1990.
  • Referências visuais: docs/screenshots/, com accent Ujimu amarelo em vez da côr de referência.
Base técnica

Preservar a arquitectura de produto existente

  • Manter Nuxt 4, TypeScript, Nuxt UI, SQLite e APIs server-side existentes.
  • Não alterar contratos de chat, quotas, histórico, ingestão, citações ou billing mock nesta reformulação.
  • Reestruturar a camada visual e de navegação em torno de componentes Nuxt UI.
  • Adicionar páginas ou componentes de apresentação quando isso reduzir o tamanho e a fragilidade de pages/index.vue e pages/admin/index.vue.
Componentes de chat

Validação técnica inicial

  • O pacote instalado @nuxt/ui@4.7.1 inclui componentes de chat: UChatMessages, UChatMessage, UChatPrompt e UChatPromptSubmit.
  • Os tipos destes componentes esperam mensagens no formato UIMessage do pacote ai, usando parts.
  • O modelo interno actual usa ChatMessage próprio com texto, citações, estado e IDs de histórico.
  • Decisão provável: criar um adaptador visual de mensagens, sem mudar o contrato do endpoint /api/chat nesta fase.
Antes de implementar, a documentação oficial do Nuxt UI deve ser consultada para confirmar os padrões recomendados e evitar APIs obsoletas.
Mapa de superfícies

Quatro superfícies, uma linguagem

ChatSuperfície principal: mensagens, prompt, especialista, citações, fila e anúncios em linha.
DrawerNavegação a pedido: histórico, novo chat, conta, subscrições, segurança e admin quando aplicável.
SubscriçõesPágina própria para plano, estado, aviso de expiração e acções de checkout mock.
AdminConsola operacional para especialistas, fontes, ingestão, analytics e readiness.
Chat shell

Estrutura proposta

  • Topo compacto com botão de drawer, nome do produto e acções contextuais mínimas.
  • Área central de mensagens com largura controlada e scroll dedicado.
  • Quando não existem mensagens, mostrar cartão informativo do especialista seleccionado dentro da área de mensagens.
  • Prompt fixo no fundo, com dropdown de especialista, textarea, submit, estado de quota e erros.
  • Sem hero separado; a primeira interacção é escrever a pergunta.
Drawer

Navegação a pedido

  • Drawer abre por botão, em desktop e mobile; não há barra lateral persistente.
  • Conteúdo do drawer: novo chat, histórico, subscrições, segurança da conta, admin e terminar sessão quando aplicável.
  • Login aparece como acção contextual no drawer ou em modal quando uma operação o exige.
  • Histórico mantém limite de 20 conversas por especialista, mas deixa de competir com a leitura da resposta.
Mensagens

Fluxo de conversa e publicidade

  • Mensagens do utilizador e do assistente vivem no painel principal de mensagens.
  • Citações ficam associadas ao fim da resposta do assistente, mantendo a política actual.
  • Anúncios entram como itens inertes entre respostas do assistente elegíveis.
  • O contador de anúncios usa respostas do assistente, escolhendo o próximo intervalo entre 5 e 10 respostas.
  • Ao editar uma pergunta anterior, o estado visual deve mostrar que a continuação será substituída.
Subscrições e login

Separar tarefas de conta do chat

  • Criar página dedicada de subscrição para plano, estado actual, aviso de expiração e acções de checkout mock.
  • Remover blocos de subscrição permanentes da página principal de chat.
  • Login passa a modal ou página a pedido, accionado por quotas, histórico, subscrição, segurança ou admin.
  • Manter OTP e passkeys existentes; a reformulação não cria novo método de autenticação.
Admin

Consola operacional em vez de painel único denso

  • Usar componentes Nuxt UI para navegação, cards, formulários, tabelas, badges, tabs e modais.
  • Organizar por tarefas: especialistas, fontes/conversão/ingestão, analytics/content gaps e operações.
  • Preferir lista + detalhe a formulários longos sempre visíveis.
  • Mostrar estados de fonte, erros e acções administrativas com hierarquia clara.
  • Manter todas as verificações de admin no servidor.
Risco técnico

Principal risco: adaptação ao formato de chat do Nuxt UI

  • Os componentes do Nuxt UI parecem optimizados para UIMessage do pacote ai.
  • O backend actual emite NDJSON próprio com eventos delta, citation, history e done.
  • A adaptação deve ser feita na camada de apresentação para evitar mexer no motor de grounding.
  • Se o componente de chat não aceitar bem citações e anúncios, usar os componentes menores de Nuxt UI para compor a experiência sem abandonar o design system.
Decisões fechadas

Iteração 2 da arquitectura

  • O histórico de conversas fica no drawer; não haverá página dedicada de pesquisa/listagem nesta reformulação inicial.
  • O admin passa a subpáginas sob /admin, em vez de continuar como página única densa.
  • A página de subscrição usará a rota /subscription.
  • Será criado um adaptador visual para converter as mensagens actuais para o formato esperado pelos componentes UChat* do Nuxt UI, mantendo o backend de chat como está.
Registo de iteração

Iterações 1–2

  • Iteração 1: criado o rascunho de arquitectura a partir do brainstorming aprovado.
  • Iteração 1: identificado o risco principal no encaixe entre mensagens Ujimu e componentes UChat*.
  • Iteração 2: histórico confirmado no drawer.
  • Iteração 2: admin confirmado em subpáginas.
  • Iteração 2: rota de subscrição confirmada como /subscription.
  • Iteração 2: aprovado adaptador visual para mensagens, sem alterar o backend de chat.
