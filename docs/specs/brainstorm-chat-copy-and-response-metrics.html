Brainstorm vivo

Cópia de perguntas e métricas de resposta

Estender as acções da conversa: copiar perguntas, e mostrar no fim da resposta mais recente quanto tempo o agente demorou e, quando disponível, quantos tokens foram usados.

Objectivo actual

Mais transparência na conversa

  • Permitir copiar perguntas do utilizador, tal como já se copiam respostas.
  • Mostrar duração da resposta no fim da mensagem do assistente.
  • Mostrar tokens apenas se o servidor tiver dados fiáveis.
  • Preservar fluxo, histórico, citações e edição de perguntas.
Contexto governante

Fontes verificadas

Sem docs/wiki

Não existe docs/wiki/; o contexto vem de AGENTS.md, specs existentes e código actual.

Spec anterior

brainstorm-chat-message-actions.html cobre copiar respostas com fontes; esta extensão não deve reabrir decisões fora do escopo.

Base técnica observada

Onde o comportamento vive hoje

  • pages/index.vue controla mensagens, fluxo, cópia de resposta e UI de acções.
  • utils/chat-copy.ts formata respostas com citações para a área de transferência.
  • server/utils/chat/engine.ts emite eventos NDJSON de resposta.
  • server/utils/chat/pi-runner.ts recebe eventos Pi e pode observar metadados do fornecedor.
Direcções possíveis

Três níveis de ambição

  • Mínimo: copiar perguntas; medir duração no cliente desde envio até done.
  • Servidor exacto: o servidor mede duração da execução e emite metadados antes de done.
  • Tokens: incluir contagem só quando o executor recebe metadados fiáveis do fornecedor; caso contrário, omitir.
Recomendação actual

Seguro e incremental

  • Copiar pergunta deve reutilizar copyTextToClipboard com texto simples.
  • Duração deve ser medida desde o envio até a resposta terminar.
  • Tokens devem aparecer apenas quando existirem dados fiáveis; se não existirem, a métrica é omitida.
  • Não persistir métricas no histórico; mostrar apenas a resposta mais recente da sessão.
Decisões fechadas

Comportamento esperado

  • Tempo contado desde o envio da pergunta até a resposta terminar.
  • Métricas não ficam guardadas no histórico retomado.
  • Quando tokens não estiverem disponíveis, não mostrar nada sobre tokens.
  • Formato visual: 3,2 s · 1 248 tokens.
Exclusões propostas

Não mexer agora

  • Não acrescentar regeneração de respostas.
  • Não alterar quotas nem usar tokens para cobrança.
  • Não expor custo do fornecedor ao utilizador.
  • Não mudar o formato das citações nem a política de grounding.
Iteração 1

Pedido recebido

  • O utilizador pediu copiar também a pergunta.
  • O utilizador pediu tempo no final de cada resposta.
  • O utilizador pediu número de tokens “se possível”.
  • Brainstorm iniciado; perguntas abertas registadas.
Iteração 2

Respostas recebidas

  • Duração: desde o envio até a resposta terminar.
  • Histórico: não persistir métricas; interpretação actual é mostrar só na última resposta da sessão.
  • Tokens: omitir quando indisponíveis.
  • Formato escolhido: 3,2 s · 1 248 tokens.
Aprovação

Brainstorm aprovado

  • O utilizador aprovou o deck na conversa.
  • Interpretação aceite: métricas só na resposta mais recente da sessão.
  • Próximo passo Zafir: desenho e arquitectura sobre a base existente.
Iteração 3

Arquitectura global não reaberta

  • O utilizador escolheu usar a arquitectura actual como base de referência.
  • A decisão evita mudanças de produto e mantém o trabalho cirúrgico.
  • O desenho mínimo foi registado em docs/specs/chat-copy-and-response-metrics-architecture.html.
