Arquitectura

Cópia de perguntas e métricas de resposta

Usar a arquitectura actual como base de referência e acrescentar apenas o estado mínimo necessário para a conversa.

Origem

Brainstorm aprovado

  • Referência: docs/specs/brainstorm-chat-copy-and-response-metrics.html.
  • O utilizador escolheu não rever a arquitectura global.
  • Decisão: preservar a estrutura actual de conversa em fluxo, histórico e citações.
  • Não existe docs/wiki/; aplicam-se AGENTS.md, especificações e código actual.
Base

Fronteiras existentes

UI

pages/index.vue mantém mensagens, fluxo, histórico, acções e estado de cópia.

Área de transferência

utils/chat-copy.ts já concentra a escrita na área de transferência e formata respostas com fontes.

Fluxo

server/utils/chat/engine.ts e types.ts definem eventos NDJSON da resposta.

Pi

Eventos message_end podem trazer usage.totalTokens; se não trouxerem, a UI omite tokens.

Desenho UI

Copiar pergunta

  • Mostrar uma acção de cópia junto da pergunta do utilizador.
  • Copiar apenas o texto da pergunta, sem prefixos nem metadados.
  • Reutilizar o feedback actual: “Copiado” quando corre bem e erro curto quando falha.
  • Manter edição de pergunta separada; copiar não altera histórico nem fila.
Desenho UI

Métricas da última resposta

  • Medir no cliente com performance.now(), desde o envio até ao evento done.
  • Guardar a métrica apenas no objecto de mensagem em memória.
  • Mostrar a linha só na resposta concluída mais recente da sessão.
  • Formato: 3,2 s · 1 248 tokens; sem tokens, mostrar apenas 3,2 s.
Tokens

Opcional por contrato

  • Acrescentar um evento opcional de metadados no fluxo, sem obrigar os executores a emiti-lo.
  • O executor Pi tenta ler usage.totalTokens de mensagens finais quando existir.
  • Executores de teste podem emitir tokens para validar a UI sem depender de fornecedor externo.
  • Não estimar tokens, não mostrar custo e não usar esta métrica para quotas.
Persistência

Sem alteração de histórico

  • Não adicionar colunas à base de dados.
  • Não alterar endpoints de histórico.
  • Ao retomar uma conversa, métricas antigas não aparecem.
  • Ao fazer nova pergunta, a métrica visível passa para a nova resposta quando terminar.
API interna

Contrato mínimo

  • ChatStreamEvent ganha um evento opcional: { type: 'metrics', totalTokens?: number }.
  • ChatRunnerStreamEvent ganha o mesmo evento para executores que souberem medir tokens.
  • O evento é informativo e deve ser ignorado por clientes antigos.
  • done continua a ser o marcador de conclusão da resposta.
Exclusões

Fora deste desenho

  • Persistir métricas no histórico.
  • Mostrar tokens indisponíveis.
  • Calcular custo monetário ou expor dados do fornecedor.
  • Alterar grounding, citações, quotas ou ingestão.
Condição de sucesso

Verificável no corte

  • Há botão para copiar perguntas concluídas.
  • A resposta copiada continua a incluir fontes.
  • Apenas a última resposta concluída mostra duração.
  • Tokens aparecem quando o fluxo os envia e desaparecem quando não são enviados.
Aprovação

Desenho aprovado

  • O utilizador aprovou o desenho na conversa.
  • A arquitectura global permanece como base de referência.
  • O próximo passo é um corte único e pequeno para testes e implementação.
