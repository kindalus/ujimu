Uma cadeia verificável para converter PDFs digitalizados sem Gemini e sem publicar documentos incompletos.

Base aprovada

O contrato vem antes da ferramenta

  • OCR é obrigatório quando a camada textual não basta.
  • Todas as páginas recebem confirmação visual.
  • O revisor é o modelo definido em UJIMU_PI_INGESTION_*.
  • O modelo actual, openai-codex/gpt-5.6-sol, declara input de imagem e contexto de 272 000 tokens.
  • Português e inglês são os idiomas OCR iniciais; ilegibilidade residual reprova o documento.
Imagem do contentor

Quatro componentes, uma função cada

Poppler

Conta páginas, extrai texto nativo e renderiza imagens com pdfinfo, pdftotext e pdftoppm.

OCRmyPDF

Orquestra rotação, deskew e OCR sobre uma cópia de trabalho.

Tesseract por + eng

Produz a primeira leitura local, sem enviar o documento para outro fornecedor.

qpdf

Detecta corrupção estrutural antes e depois da normalização.

Instalação

Pacotes explícitos e reproduzíveis

apt-get install -y --no-install-recommends \ ocrmypdf \ poppler-utils \ python3-pil \ qpdf \ tesseract-ocr \ tesseract-ocr-por \ tesseract-ocr-eng

Ghostscript e bibliotecas Python entram apenas como dependências empacotadas do OCRmyPDF.

Workspace transitório

Uma página de cada vez

.ujimu/ocr/<source-hash>/ normalized.pdf current/page.png current/page.txt coverage.json draft.md
  • raw/ permanece imutável.
  • A janela de uma página limita disco, memória e contexto do modelo.
  • Imagem e OCR correntes são removidos após a decisão; o ledger conserva hashes e estado.
  • O Markdown só entra em converted/ após validação integral.
Restrição descoberta

300 DPI não chegam se a leitura reduzir a imagem

O read do Pi limita automaticamente a imagem enviada ao modelo a 2000×2000 px. Uma página A4 a 300 DPI mede aproximadamente 2480×3508 px e seria reduzida.

  • A visão geral preserva estrutura, mas pode perder caracteres pequenos.
  • A alternativa de alta precisão divide a página em quadrantes sobrepostos.
  • A decisão de cobertura deve exigir a visão geral e todos os quadrantes.
Confirmação visual

Um prompt não é prova suficiente

O runner regista a leitura bem-sucedida de cada imagem exigida e uma decisão por página no coverage.json: confirmada, corrigida ou ilegível. O número de entradas deve coincidir com pdfinfo.

  • Correcções preservam texto e estrutura visíveis.
  • O modelo não pode preencher caracteres por conjectura.
  • Uma página ilegível impede a publicação do documento.
Segurança operacional

PDF é entrada hostil

Privilégio mínimo

Continuar como UID/GID 999, sem escrita em raw/.

Recursos limitados

Concorrência unitária, timeout e limite de memória por processo.

Paths fechados

Sem paths absolutos, traversal ou symlinks.

Falha atómica

Sem mover Markdown para converted/ antes de cobertura completa.

Exclusões

Menos peças, menos entropia

  • Sem Gemini CLI ou GEMINI_API_KEY neste fluxo.
  • Sem ImageMagick: não é necessário para renderizar páginas.
  • Sem serviço OCR externo ou novo provider visual.
  • Sem ingestão parcial de um PDF reprovado.
  • Sem confiar apenas em tamanho de ficheiro ou confiança média do OCR.
Fontes técnicas

Escolhas ancoradas nos projectos oficiais

  • OCRmyPDF — OCR, rotação, deskew e sidecar.
  • Tesseract — recomenda pelo menos 300 DPI e documenta pré-processamento.
  • Poppler — ferramentas de análise, extracção e rasterização PDF.
  • qpdf — verificação sintáctica e estrutural parcial.
