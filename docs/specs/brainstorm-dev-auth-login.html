UjimuBrainstorm Zafir — login dev

Objectivo

Login de desenvolvimento sem OTP

Permitir testes locais rápidos de utilizadores e administradores, sem enfraquecer a autenticação em produção.

Valor

Porque existe

  • Acelera testes de chat, ingestão, conversão e administração.
  • Evita depender de entrega real de OTP durante desenvolvimento.
  • Mantém a regra: administração continua separada por UJIMU_ADMIN_CONTACTS.
  • Não substitui OTP, passkeys nem políticas de produção.

Contrato proposto

Variáveis de ambiente

  • UJIMU_DEV_AUTH_ENABLED=true activa o modo dev.
  • UJIMU_DEV_USER_CONTACTS lista contactos permitidos, separados por vírgulas.
  • UJIMU_ADMIN_CONTACTS continua a definir quem é admin.
  • O modo dev é recusado quando NODE_ENV=production.

Fluxo

Como funciona

  • O utilizador escolhe a acção “Entrar em modo desenvolvimento”.
  • Submete um contacto por email ou telemóvel.
  • Se o contacto estiver na allowlist dev, o backend cria/actualiza utilizador e identidade verificada.
  • O backend emite a cookie de sessão normal e devolve a sessão pública.

Segurança

Guardas obrigatórias

  • Nunca funciona em produção, mesmo com variáveis definidas.
  • Não lista contactos permitidos no browser.
  • Não conta como OTP recente, para não autorizar criação de passkeys.
  • Usa normalização igual à administração: email em minúsculas; telefone sem espaços.
  • Regista sessão com método unknown ou equivalente não-OTP.

API

Endpoint mínimo

  • POST /api/auth/dev-login
  • Body: { channel: "email" | "phone", contact: string }
  • Sucesso: resposta de sessão igual ao login normal.
  • Erros: contacto inválido, modo não activo, contacto não autorizado, produção bloqueada.

UI

Superfície no modal

  • Adicionar bloco discreto no AuthModal.vue.
  • Só mostrar quando endpoint/flag indicar modo dev activo.
  • Texto claro: “Modo de desenvolvimento”.
  • Não mostrar em produção nem quando a flag estiver desligada.

Testes

Aceitação

  • Permite login dev para contacto allowlisted em desenvolvimento.
  • Cria identidade verificada e permite admin quando também estiver em UJIMU_ADMIN_CONTACTS.
  • Rejeita contacto fora da allowlist.
  • Rejeita sempre em produção.
  • Não produz sessão OTP recente para passkeys.

Exclusões

Fora de âmbito

  • Sem login dev em produção.
  • Sem bypass para billing, quotas ou permissões admin.
  • Sem entrega real de email/SMS.
  • Sem criar passwords ou contas permanentes especiais.

Aprovação necessária
