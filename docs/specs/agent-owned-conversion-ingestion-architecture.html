Arquitectura

Pipeline llm-wiki nativo

O caminho normal passa a seguir exactamente o contrato do skill: raw/ -> converted/ -> wiki/, executado pela sessão de ingestão.

Estrutura

Directório da especialidade

  • raw/: fontes originais carregadas por administradores; só leitura para o agente.
  • converted/: Markdown gerado pelo agente, com frontmatter auditável.
  • wiki/: bundle OKF curado pelo agente.
  • ingest/state.json: índice operacional de Ujimu, não uma segunda wiki.
  • logs/: auditoria humana das sessões Pi.
Fluxo

Job único

upload
→
state pending
→
ingestion agent
→
converted + wiki
→
manifest v2
Sessão Pi

Política de ficheiros

  • Leitura: raw/, converted/, wiki/, AGENTS.md, ingest/state.json.
  • Escrita: converted/, wiki/, .ujimu/ingestion-manifest.json.
  • Listagem: raiz virtual com AGENTS.md, raw, converted e wiki.
  • bash continua fora da sessão de ingestão.
Manifesto v2

Contrato de retorno

  • processed[] inclui fonte, path convertido, hashes, estado de conversão, páginas wiki, citações e avisos.
  • failed[] inclui fonte, fase falhada, estado de conversão quando existir, código e mensagem.
  • O backend exige uma menção exacta por fonte pendente.
  • Estados parciais ou falhados não entram como fontes ingeridas.
Estado

Compatibilidade pragmática

  • Manter campos existentes de conversion para reduzir impacto de UI.
  • markdown_path passa a apontar para o path relativo em converted/ no caminho novo.
  • Adicionar metadados do skill: conversion_status, método, avisos e checksum convertido.
  • Fontes antigas continuam legíveis; fontes pendentes antigas são migradas para ingestão pelo agente.
Validação

Segurança sem endurecer conteúdo

  • Ujimu não valida tamanho mínimo, artigos extraídos ou fidelidade textual da conversão.
  • Ujimu valida fronteiras: paths, hashes, existência de ficheiros e formato de citações.
  • As regras de conversão vivem no skill llm-wiki.
  • Se o manifesto for inválido, o estado pendente é restaurado.
