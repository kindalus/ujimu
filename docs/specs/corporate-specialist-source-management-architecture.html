Arquitectura Zafir

Gestão corporativa de fontes

Extensão estreita ao modelo corporativo: admins de empresa gerem prompt e fontes dos especialistas privados da sua empresa, sem executar ingestão.

Fonte de verdade

Brainstorm aprovado

  • Deriva de docs/specs/brainstorm-corporate-specialist-source-management.html.
  • Admin corporativo gere apenas especialistas com company_id da sua empresa.
  • Não cria especialistas nem muda associação, estado, nome ou wiki type.
  • Upload substitui fonte anterior quando o nome lógico coincide.
  • Ingestão/conversão continuam reservadas ao admin Ujimu.
Princípio

Nova superfície corporativa, não /api/admin

A funcionalidade deve viver sob rotas de empresa, autorizada por requireCompanyAdmin(), mantendo a consola Ujimu separada.

UI/companies/:id/specialists lista especialistas privados da empresa.
API/api/companies/:id/specialists/** expõe só o subconjunto permitido.
Autorização

Dois checks obrigatórios

  1. O utilizador tem sessão válida e é admin da empresa pedida.
  2. O especialista pedido existe, está associado a essa empresa por company_id, e não é público nem de outra empresa.
  3. Especialistas suspensos podem aparecer para gestão de fontes? Decisão arquitectural: sim, mas continuam indisponíveis no chat público/corporativo.
Contratos API

Endpoints mínimos

GET /api/companies/:id/specialists — lista especialistas da empresa com fontes.
GET /api/companies/:id/specialists/:specialistId — detalhe de um especialista permitido.
PATCH /api/companies/:id/specialists/:specialistId — altera apenas system_prompt.
POST /api/companies/:id/specialists/:specialistId/raw — carrega/substitui fonte e actualiza estado.
Payloads

Menos campos que admin Ujimu

  • Mostrar: id, name, description, wiki_type, system_prompt, status e sources.
  • Não mostrar ou aceitar edição de company_id, citations_required, streaming_enabled ou caminhos internos.
  • Estados de fontes reutilizam o payload de ingestão existente, já sanitizado para UI.
  • Erros de autorização devolvem 404 quando o especialista não pertence à empresa, para não revelar especialistas alheios.
Prompt

Edição global do especialista privado

  • O system_prompt editado é o do ficheiro specialist.yaml desse especialista.
  • Como o especialista é privado de uma empresa, o efeito prático é corporativo.
  • Se o admin Ujimu reassociar o especialista no futuro, o prompt acompanha o especialista.
  • Não criar variantes por empresa neste slice.
Upload

Mesmo motor, autorização diferente

  • Reutilizar validação de extensão e content-type dos uploads admin.
  • Reutilizar storeRawSource(..., replaceExisting: true).
  • Depois do upload, correr só scanSpecialistRawSources() para actualizar estado.
  • Não chamar conversão, ingestão nem fila de jobs.
  • UI deve dizer: “Aguarda processamento pelo admin Ujimu.”
Auditoria

Registos separados para admins corporativos

  • Criar company_admin_audit_events para prompt e upload corporativo.
  • Campos: actor, empresa, especialista, acção, timestamp e metadata sanitizada.
  • Metadata de upload inclui nome relativo e bytes, nunca conteúdo.
  • Metadata de prompt inclui campo alterado, nunca prompt anterior ou novo.
UI

Página de especialistas da empresa

ListaCards com nome, estado, contagem de fontes e botão gerir.
DetalheEditor de prompt, upload de ficheiro e lista de fontes/estados.
NavegaçãoLink em /companies/:id visível para admins da empresa.
Sem ingestãoNenhum botão de conversão, ingestão, apagar ou criar especialista.
Testes

Critérios verificáveis

  • Admin da empresa lista apenas especialistas da sua empresa.
  • Membro não-admin e empresa errada não podem ver nem alterar.
  • PATCH só aceita system_prompt.
  • Upload cria/substitui fonte, actualiza estado, mas não agenda ingestão.
  • UI contém as rotas e não contém acções de ingestão/conversão.
Exclusões

Guardar foco

  • Sem criação, suspensão, associação ou apagamento de especialistas por empresa.
  • Sem edição de campos fora de system_prompt.
  • Sem execução de Pi, conversão, ingestão ou jobs por admin corporativo.
  • Sem variantes de prompt por empresa.
  • Sem alteração a chat, quota, billing ou citações.
