UjimuArquitectura — login dev

Direcção

Reutilizar autenticação existente

O login dev cria a mesma sessão que o resto da aplicação, mas só em desenvolvimento e sem marcar a sessão como OTP recente.

Backend

Contrato

  • GET /api/auth/dev-login devolve apenas se o modo dev está activo.
  • POST /api/auth/dev-login recebe canal e contacto.
  • O endpoint valida contacto, allowlist e ambiente antes de criar sessão.
  • Em produção, o POST é recusado mesmo com variáveis definidas.

Dados

Sem novo esquema

  • Reutilizar tabelas users e user_identities.
  • Criar identidade verificada quando o contacto dev é aceite.
  • Não criar tabelas, passwords, papéis ou permissões novas.
  • UJIMU_ADMIN_CONTACTS continua a autorizar administração.

Sessão

Não simular OTP

  • A cookie é ujimu_session, igual ao login normal.
  • A sessão não recebe authMethod: otp.
  • /api/auth/session deve expor authMethod: unknown e recentOtpAuthenticated: false.
  • Assim, o login dev não habilita criação de passkeys.

Frontend

Modal existente

  • AuthModal.vue consulta se o modo dev está activo.
  • Mostra botão discreto “Entrar em modo desenvolvimento”.
  • Usa o mesmo campo de email/telemóvel do formulário.
  • Não mostra nem revela a lista de contactos permitidos.

Verificação

Critérios

  • Testes de backend para sucesso, admin por allowlist, recusa fora de allowlist e bloqueio em produção.
  • Teste de UI para superfície dev no modal.
  • Suite completa, typecheck, build e audit.
