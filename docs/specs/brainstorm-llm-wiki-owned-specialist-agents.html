Brainstorming aprovado · iteração 4

llm-wiki cria o AGENTS.md

Clarificar a responsabilidade: a skill cria o contrato da wiki; o Ujimu fornece as regras específicas de consulta que entram no mesmo ficheiro.

Objectivo e valor

Um contrato único, sem duplicar o scaffold

Para o administrador

Cada novo especialista nasce com uma wiki coerente e regras de consulta previsíveis.

Para o runtime

AGENTS.md continua a entrar automaticamente no contexto Pi do especialista.

Sucesso

O prompt atribui explicitamente o scaffold à llm-wiki e exige o bloco Ujimu.

Segurança

A inicialização falha se faltar qualquer regra obrigatória.

Direcções consideradas

Três formas de fornecer regras

A · Bloco no prompt

A llm-wiki gera o ficheiro e incorpora um bloco canónico fornecido pelo Ujimu. Menor alteração.

B · Escrita posterior

O backend edita o ficheiro depois do agente. Determinista, mas divide a autoria e pode danificar o esquema.

C · Segundo ficheiro

Separa responsabilidades, mas o carregamento e a precedência tornam-se menos evidentes.

Recomendação

Direcção A, acompanhada de validação explícita da saída.

Âmbito mínimo

Alterar só a inicialização

  • Mandar ler e usar a skill llm-wiki com o preset configurado.
  • Fixar AGENTS.md como ficheiro de esquema.
  • Injectar persona, wiki como fonte exclusiva, insuficiência de evidência, citações, caminhos internos e unslop.
  • Manter o protocolo NDJSON actual para citações estruturadas, com texto simples aceite como hoje.
  • Validar todas as regras obrigatórias antes de activar o especialista.

Limites e pressupostos

O que fica de fora

Sem migração automática

Não reescrever AGENTS.md de especialistas já existentes.

Sem novo formato

Não criar DSL, template engine ou ficheiro de configuração adicional.

Sem alteração global

Não modificar o system prompt global nem os prompts de ingestão.

Compatibilidade

Manter sourceFile como metadado interno, nunca como texto destinado ao utilizador.
