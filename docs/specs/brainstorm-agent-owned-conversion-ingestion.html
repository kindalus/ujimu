Conversão e ingestão pelo agente llm-wiki

Adaptar Ujimu ao novo contrato do skill llm-wiki: o agente de ingestão converte raw/ para converted/ e só depois mantém wiki/.

Contexto governante

O skill mudou a arquitectura

  • llm-wiki exige quatro camadas: raw/, converted/, wiki/ e schema local.
  • A regra é obrigatória: raw/ -> converted/ -> wiki/.
  • Nunca se ingere directamente de raw/; a conversão é a única operação que lê fontes originais.
  • O repositório Ujimu ainda tem código legado de conversão separada para Markdown dentro de raw/.
Objectivo

Menos endurecimento de conversão no backend

  • Remover a conversão obrigatória gerida por Ujimu do caminho normal de ingestão.
  • Deixar o agente, guiado pelo skill, decidir como criar os artefactos converted/.
  • Manter Ujimu como guarda de fronteira: uploads, sandbox, estado operacional e validação de manifesto.
  • Preservar citações e rastreabilidade usadas no chat.
Decisão principal

Uma sessão de ingestão faz o ciclo completo

  • O botão «Executar ingestão» dispara um job único.
  • A sessão Pi de ingestão lê raw/, converted/, wiki/ e ingest/state.json.
  • A sessão escreve converted/, wiki/ e .ujimu/ingestion-manifest.json.
  • O backend não interpreta o conteúdo convertido, apenas valida contractos e caminhos.
Fronteiras

O que continua a ser de Ujimu

  • raw/ continua imutável para o agente.
  • O backend valida que cada fonte pendente aparece uma vez no manifesto.
  • O backend valida paths seguros, hashes, páginas wiki existentes e citações não vazias.
  • Falhas de conversão ficam retryáveis no state.json.
Exclusões

Não resolver neste corte

  • OCR e ferramentas novas de extracção binária.
  • Remoção imediata do endpoint legado de conversão manual.
  • Alterações de chat, quotas, pagamentos ou UI corporativa.
  • Persistir conhecimento de conversão fora de state.json e dos ficheiros converted//wiki/.
Aprovação operacional

Direcção escolhida

  • Implementar o caminho normal com conversão+ingestão pelo agente.
  • Conservar validação de manifesto como controlo de segurança.
  • Usar manifesto v2 para transportar metadados de conversão.
  • Manter compatibilidade mínima com runners antigos durante a transição.
